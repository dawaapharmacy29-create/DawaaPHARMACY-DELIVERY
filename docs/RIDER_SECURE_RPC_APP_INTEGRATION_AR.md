# تحديث أمان صفحة الدليفري — Session Token + RPC

تم تعديل صفحة الدليفري لتستخدم مسارًا آمنًا يعتمد على `session_token` ودوال Supabase RPC كلما كانت متاحة، مع الإبقاء على fallback للتشغيل القديم حتى لا يتوقف التطبيق.

## ما تم تعديله في التطبيق

1. تسجيل دخول الدليفري يحفظ `session_token` داخل جلسة الدليفري.
2. لوحة الدليفري تحاول تحميل البيانات من:
   - `rider_get_dashboard_data(session_token)`
3. تسجيل الحضور والانصراف يحاول استخدام:
   - `rider_check_in_out(session_token, check_in/check_out)`
4. بحث العملاء يحاول استخدام:
   - `rider_search_customers(session_token, query)`
5. تسجيل الأوردر يحاول استخدام:
   - `rider_create_order(session_token, ...)`
6. إذا لم تكن الدوال متاحة، يستخدم التطبيق المسار القديم مؤقتًا حتى لا يتوقف التشغيل.

## ملاحظات أمان

- لم يتم تنفيذ `REVOKE` قوي في هذا التحديث حتى لا يتعطل التطبيق لو بقي جزء قديم يقرأ الجداول مباشرة.
- بعد التأكد أن كل وظائف الدليفري تعمل من التطبيق الجديد، يمكن تنفيذ Migration لاحقة لإغلاق direct table access عن `anon`.

## الاختبارات المطلوبة

- تسجيل دخول دليفري.
- تسجيل حضور.
- تسجيل انصراف.
- بحث عن عميل باستخدام `*`.
- تسجيل أوردر بعد الحضور.
- فتح لوحة الدليفري والتأكد من ظهور بيانات اليوم والدورة.
